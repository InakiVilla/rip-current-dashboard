Rip Current Detection Model Using MobileNetV3-Large with Incrementing Dataset Sizes

How much labeled footage does a lightweight neural network need before it can reliably tell a rip current from ordinary surf? One fixed model, four experiments, and nested datasets from 500 to 20,000 images.

Rean G. Coyacot and Vicente Iñaki B. Villa Adviser: Christine F. Peña, MMath BS Computer Science, Department of Computer, Information Sciences and Mathematics, University of San Carlos, 2026

Abstract

ModelMobileNetV3-Large, ImageNet pretrained
TaskBinary classification: rip current or no rip current
DataRipVIS, nested sets of 500 to 20,000 images

Rip currents are hazardous coastal phenomena that require efficient detection systems to support coastal safety efforts. This study investigates the performance of a lightweight deep learning model for binary rip current classification using incrementally increasing dataset sizes.

A MobileNetV3-Large architecture was evaluated across eight dataset sizes ranging from 500 to 20,000 images. The study examines the influence of dataset scaling, dataset construction strategy, and training optimization techniques on classification performance and computational efficiency.

Four experimental configurations were compared: baseline training, augmented training, improved dataset construction, and combined dataset-training optimization.

Why dataset size, not a bigger model

Rip currents cause most surf-zone rescues, yet beachgoers rarely recognize them. Deep learning can spot them in coastal imagery, but most published work relies on heavy models and very large annotated datasets.

This study holds the model fixed and varies only the amount of labeled data. MobileNetV3-Large, initialized with ImageNet weights, is fine-tuned as a binary classifier (Rip Current vs Non-Rip Current) under identical preprocessing, training, and evaluation at every dataset size. The aim is to see how performance grows with data and where additional images start returning smaller gains.

How performance is measured

  • AccuracyShare of all test images classified correctly.
  • PrecisionOf the images flagged as rip currents, how many really were. Low precision means false alarms.
  • RecallOf the real rip currents, how many the model caught. Low recall means missed hazards.
  • F1-scoreBalance of precision and recall.
  • SpecificityOf the images without a rip current, how many the model correctly cleared. A model that calls everything a rip current scores 0%, so this exposes runs that never learned the calm-water class.
  • F2-scoreWeighs recall more heavily than precision, because missing a rip current is the costlier error. This is the headline metric throughout the page.

Two ways of building the datasets

Every dataset is nested: each smaller set is fully contained in the next larger one, so a change in performance reflects added data rather than a different random draw.

Original pipeline

Frames are the sampling unit. Eight nested sizes, 77% Rip Current to 23% Non-Rip Current, split 70 / 15 / 15.
  1. RipVIS dataset
  2. COCO annotations
  3. Frame extraction
  4. Fill each quota video by video
  5. Nested selection
  6. 500 to 20,000

Frames were extracted using the provided COCO annotations and sorted into rip-current and non-rip-current classes. Each class quota was then filled one video at a time, taking that video's frames in order before moving to the next. The first videos in line therefore supplied most of the images, and smaller datasets drew on only a few clips.

Limitations found

Video contribution imbalanceFilling quotas video by video let one clip supply dozens of frames while others supplied few or none.
Temporal similarityFrames from the same clip are often close in time and look almost the same.
Potential dataset biasA bigger dataset could mean more frames of the same scenes without a matching increase in visual variety.

V2 pipeline

Every dataset draws the same number of frames from the same set of videos. Eight nested sizes.
  1. RipVIS dataset
  2. Source videos
  3. Video-level split
  4. Balanced video sampling
  5. Nested dataset creation
  6. 500 to 20,000

Instead of filling quotas one video at a time, V2 takes an equal share of frames from each source video, so every dataset size covers the same range of scenes. Both pipelines draw their test images from the same source videos; what changed is how evenly those videos are represented.

  1. Keep each video in one splitEvery frame of a video stays in exactly one of train, validation, or test, so the model is never tested on a clip it trained on.
  2. Take an equal share from every videoEach video contributes the same number of frames, so no single clip dominates a dataset and small datasets still cover every scene.
  3. Grow the nested sets500 ⊂ 1,000 ⊂ 1,500 ⊂ 2,000 ⊂ 2,500 ⊂ 5,000 ⊂ 10,000 ⊂ 20,000 images, with extra small sizes to see the early part of the learning curve.
  4. Audit before trainingAutomated checks confirm the dataset is sound before any model sees it.

Reading these results carefully

The pipelines weight test videos differently

Both pipelines test on frames from the same source videos, but not the same frames. The original test sets are dominated by whichever clips came first, while V2 spreads the test images evenly across clips. A score in each pipeline therefore rewards different videos, so scaling trends are most reliable within a pipeline.

Class imbalance sets a high floor

With roughly 77% rip-current images, a model that always answers "rip current" reaches about 77% accuracy and an F2-score near 94%. Recall and F2 should be read against that reference, and precision shows whether the model actually learned to recognise calm water.

A few videos drive the errors

Each test set draws on only four non-rip videos and about twenty rip videos. In the baseline at 20,000 images, all 54 false alarms came from one non-rip video (NR-002) and 115 of the 137 missed rip currents came from one rip video (142). Shifts between sizes often reflect how those clips are handled rather than general learning.

One run per condition

Each point comes from a single training run. Small differences between neighbouring sizes may fall within run-to-run variation, so the overall shape of the curve says more than any single step.

Scope

Findings apply to MobileNetV3-Large on RipVIS-derived frames at the tested sizes. They do not identify a universally sufficient dataset size, and further validation is needed before applying them to other beaches or to live monitoring.
